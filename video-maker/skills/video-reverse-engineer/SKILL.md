# 短视频分镜逆向工程全流程

将一条对标带货短视频，经过"逆向拆解 → 无损改写 → I2V提示词生成"三步，产出可直接用于图生视频工具的导演分镜稿。

## 环境准备

步骤1需要调用 **Gemini API** 来分析视频（Claude 无法直接处理视频文件）。

### 依赖安装
```bash
pip install google-genai
```

### API Key 配置
在项目根目录 `.env` 中设置 `GEMINI_API_KEY`（从 https://aistudio.google.com/apikey 获取）。脚本会自动从根目录 `.env` 加载。

### 推荐模型
- `gemini-2.5-pro`（默认，最佳质量，适合详细分析）
- `gemini-2.5-flash`（更快，适合批量处理）

## 使用前须知

本技能处理的是**已有视频的结构化分析**，需要用户提供：
- **必须**：对标视频文件（或视频的文字描述/截图）
- **可选**：品牌/产品配置信息（用于第二步改写时替换产品）
- **可选**：人物参考图 + 商品参考图（用于第三步 I2V 提示词）

如果用户只提供了视频但没有后续素材，前两步仍可完成，第三步可在获得素材后继续。

## 全流程概览

```
输入：对标视频
    ↓
[步骤1] Gemini API 分析视频 → 输出0(设定卡) + 输出1(脚本表) + 输出2(Shot表) + 输出3(自检)
    ↓
[步骤2] Claude 无损改写 → 在Shot表末尾新增4列(改写台词/翻译/参考帧/依据)
    ↓
[步骤3] Claude I2V提示词 → 逐Shot输出导演分镜口述稿(英文+中文核对)
    ↓
输出：完整的可执行分镜包
```

**分工说明**：步骤1由 Gemini 完成（因为需要视频理解能力），步骤2和步骤3由 Claude 完成（擅长结构化改写和提示词生成）。

## 开始前：确认范围

先问用户需要执行哪些步骤：
1. 仅步骤1（逆向拆解分析）
2. 步骤1+2（拆解+改写）
3. 全部三步（拆解+改写+I2V提示词）

如果用户不确定，默认执行全部三步。

## 步骤1：逆向拆解（Gemini 执行）

**角色**：短视频分镜逆向工程师（Reverse Storyboard Engineer）

**阅读详细规则**：执行前必须先 `Read` 文件 `references/step1-reverse-analysis.md`

### 执行方式：调用 Gemini API

使用内置脚本 `scripts/gemini_analyze_video.py` 自动完成视频分析：

```bash
# 基本用法
python scripts/gemini_analyze_video.py <视频文件路径>

# 指定输出路径和模型
python scripts/gemini_analyze_video.py ./video.mp4 --output ./step1_result.md --model gemini-2.5-pro
```

脚本会自动：
1. 检测视频文件大小，选择内联（<20MB）或 File API 上传（>=20MB）模式
2. 将完整的步骤1 prompt 发送给 Gemini，获取结构化分析结果
3. 保存为 Markdown 文件

**执行完成后**：Claude 读取 Gemini 输出的 Markdown 文件，检查质量，必要时手动补充或修正，然后进入步骤2。

### 核心产出
Gemini 会按顺序输出：

1. **时长锁定（Time Lock）**—— 先确定全片真实总时长 T（秒），作为所有时间戳的上限
2. **输出0：全片统一设定卡** —— 非表格，涵盖基础信息/表达节奏/视觉统一/音频统一/合规约束
3. **输出1：逐句脚本证据表** —— Markdown表格，每行一句原始台词（含时间轴+翻译+屏幕文字+关键信息）
4. **输出2：分镜头逆向主表** —— Markdown表格，每行一个Shot，覆盖整条视频，含近40个维度字段
5. **输出3：自检清单** —— 逐条验证覆盖性、忠实度、翻译一致性、映射一致性

### 关键原则
- Shot 以真实剪辑切点为边界，不使用固定时长分段
- `visual_content_description` 写"看见什么+怎么变化"，不写生成提示词
- `original_text` 不得改写、润色、压缩
- Shot 必须覆盖 [0, T] 全区间，无缝衔接，无遗漏

### 质量检查（Claude 执行）
Gemini 返回结果后，Claude 需要检查：
- Shot 时间覆盖是否完整（首Shot从0开始，末Shot到T结束）
- 表格字段是否齐全（39列 Shot 表）
- 自检清单是否全部通过
- 若有问题，Claude 可直接修正或要求 Gemini 重新分析

## 步骤2：无损改写（Claude 执行）

**角色**：短视频分镜无损改写器（Reverse Rewrite by Shot）

**阅读详细规则**：执行前必须先 `Read` 文件 `references/step2-lossless-rewrite.md`

### 核心任务
在步骤1的 Shot表 基础上，逐Shot改写口播台词，新增4列：

| 新增列 | 说明 |
|--------|------|
| `rewrite_vo_target_language` | 改写后的目标语言口播 |
| `rewrite_vo_zh_translation` | 改写台词的中文翻译（用于长度校验） |
| `ref_frame_timestamp_sec` | 参考帧时间戳（秒，1位小数） |
| `ref_frame_basis` | 参考帧选择依据（至少3点） |

### 关键约束
- **不照抄**：改写后不能与原文高度重复，但复用结构与节奏
- **不打乱**：不跨Shot搬运信息，不改变时间顺序
- **时长一致**：`rewrite_vo_zh_translation` 字数必须在原 `dialogue_vo_zh` 的 90%-110%
- **情绪对齐**：改写后的语气/节奏必须与该Shot的 `emotion_state` 一致
- **逻辑链不断**：痛点→反转→方案→证据→CTA，每个Shot承担的环节不变
- **硬信息不删**：品牌/产品名/规格/价格/优惠/购买动作必须保留
- **无口播Shot**：改写列写"（无口播）"，不得强行新增口播

如果用户提供了**品牌/产品配置（输入C）**，则执行"场景化逻辑置换"——将原视频的底层逻辑框架迁移到用户产品的场景中。未提供则只做去重改写。

## 步骤3：I2V 提示词生成（Claude 执行）

**角色**：短视频分镜模板复刻导演（Image-to-Video Director）

**阅读详细规则**：执行前必须先 `Read` 文件 `references/step3-i2v-prompts.md`

### 核心任务
基于最终 Shot表，逐Shot输出"自然语言图生视频提示词"，格式像导演口述分镜。

### 输出结构

先输出 **GLOBAL_LOCK_CARD**（全片统一锁），然后逐Shot输出：

```
[SHOT {shot_id}]
(1) REFERENCE_FRAME_INFO     — 参考帧时间戳与指导
(2) I2V_PROMPT_FOR_MODEL_EN  — 英文导演分镜口述稿
(3) I2V_PROMPT_ZH_CHECK      — 中文逐句核对版
(4) SELF_CHECK_HINT           — 一行中文自检
```

### 五大锁定机制
1. **人物锁**：全片同一主角，脸/发型/肤色/穿搭一致
2. **商品锁**：所有产品以商品参考图为唯一真相
3. **禁包装锁**：参考图没有的包装/配件/标签一律禁止
4. **画面统一锁**：画幅/色调/光线/质感一致，运镜克制
5. **音画同步锁**：有口播Shot必须逐字说出台词，口型同步

### 英文提示词写作规范
- 6-10句，每句只干一件事，像导演口述
- 必须包含：Timecode + Visual + Dialogue(条件) + SFX/Audio(按需)
- 有口播必须写：`Spoken dialogue (say EXACTLY, word-for-word): "..."`
- 有商品必须写两条商品硬锁句（见 references 详细内容）

---

## 输出格式

所有表格使用 **Markdown 表格**格式。建议最终输出保存为 `.md` 文件供用户下载。

如果内容过长，可以按步骤拆分为多个文件：
- `step1_reverse_analysis.md`
- `step2_rewrite.md`
- `step3_i2v_prompts.md`

## 自检清单（每步结束后必须执行）

每个步骤结束后都要输出对应的自检清单（详见各步骤的 reference 文件）。自检必须逐条给出"通过/不通过"并附证据。不通过的必须在输出前修复。
