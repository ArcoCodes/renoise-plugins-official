## 输入说明

本步骤接收两份或三份输入：

- **输入A**：原始对标视频（原语言带货短视频）
- **输入B**：步骤1产出的输出2（分镜头逆向主表），包含 shot_id / start_sec / end_sec / dialogue_vo_original / dialogue_vo_zh / emotion_state / shot_goal 等列
- **输入C（可选）**：品牌/产品配置。若提供则执行场景化逻辑置换；若未提供则只做去重改写

## 新增4列填写规则

在"保留原Shot表所有列不变"的基础上，在表格最后新增四列：

### 列1：rewrite_vo_target_language
- 目标语言 = `primary_language`（原视频口播语言）
- 无口播Shot：必须填写"（无口播）"，不得新增口播
- 有口播Shot：按规则无损改写、去重、保持长度与情绪

### 列2：rewrite_vo_zh_translation
- 只翻译 `rewrite_vo_target_language`，忠实表达，不增删信息点
- 无口播：填写"（无口播）"
- **长度校验**：字数必须在原 `dialogue_vo_zh` 的 90%-110% 范围内

### 列3：ref_frame_timestamp_sec
- 输出绝对时间戳（秒，保留1位小数）
- 必须在该Shot的 `start_sec` 与 `end_sec` 之间
- 选择"最清晰 + 产品最完整入镜 + 动作关键瞬间"的帧
- 避免：切镜瞬间、运动模糊、严重遮挡、过曝过暗、字幕遮挡产品

### 列4：ref_frame_basis
- 中文填写，至少包含3点可执行依据：
  1. 产品/人物状态（如：正面完整入镜、LOGO清晰）
  2. 动作节点（如：开箱/按压/对比停顿瞬间）
  3. 画面质量（如：手部停住、清晰无糊、光线均匀）
- 可补充：为什么适合作为后续I2V的参考帧

## 改写硬规则

### 1. 不允许照抄
改写后不能与原文高度重复，但要复用结构与节奏。允许保留硬信息（品牌/产品名/规格/价格/优惠/购买动作），其余表达必须同义改写与口语重组。

### 2. 不允许打乱时间顺序
不得把后面Shot的内容提到前面，不得跨Shot搬运信息。每个Shot只改写它自己承担的功能与信息。

### 3. 时长强制一致
以该Shot的 `dialogue_vo_zh` 为长度基准。`rewrite_vo_zh_translation` 的字数必须控制在 90%-110% 范围内。

### 4. 情绪/语气/节奏一致
必须与该Shot的 `emotion_state`、`language_style`、`emphasis_notes` 一致（紧迫/兴奋/笃定/撒娇等），保持"同款口播感"。

### 5. 逻辑链条不能断
痛点 → 反转/钩子 → 解决方案 → 结果/证据 → 行动号召（CTA）。每个Shot承担的环节不变，不得移位。

### 6. 高信息密度Shot
宁可用更口语的表达承载信息，也不要删逻辑。不允许为了顺口而删掉硬信息点。

### 7. 逐Shot一一对应
Shot数量必须一致。不得漏Shot、合并Shot、新增Shot。shot_id 顺序严格时间递增。

### 8. 全片连贯
改写时考虑相邻Shot之间的承接关系，按shot_id拼接后应自然连贯。不出现突然跳话题/突兀转折/指代不明/前后重复开场。

### 9. 连接句策略
如果原视频在Shot之间有承接（"所以/然后/重点来了"），改写版必须保留同类承接方式，但换一种说法。

## 品牌配置与场景化替换

如果用户提供了输入C（品牌/产品配置），则执行场景化逻辑置换：

### 配置模板
```
品牌/产品名称: [填写]
产品核心卖点: [最多3条]
目标用户群体: [填写]
痛点一: [填写]
痛点二: [填写]
痛点三: [填写]
```

### 替换机制
- 原脚本的"错误做法" → 替换为本行业用户"常见误区"
- 原脚本的"正确做法/神器" → 替换为"本产品/本方案"
- 原脚本的"最终效果" → 替换为本产品带来的"理想状态"

### 替换原则
- 情感一致：改写后情感基调与原视频一致
- 句式一致：保留原视频句式结构，仅修改措辞与关键名词
- 爆款要素保留：确保每句改写后效果不低于改写前
- 精准删除：仅删除/替换明显的品牌名/人名/产品名等硬标识

## 逐Shot改写步骤

### 步骤1：拆解该Shot功能
- 读取 `shot_goal` / `emotion_state` / `emphasis_notes` / `dialogue_vo_original` / `dialogue_vo_zh`
- 判断属于：钩子/痛点/方案/证据/结果/CTA 的哪一环

### 步骤2：标记关键信息
- 硬信息：品牌/产品名/规格/价格/优惠/购买方式/时间限制/对比点
- 屏幕文字信息：改写不得与 `on_screen_text_graphics` 冲突

### 步骤3：逐Shot无损改写
- 先产出 `rewrite_vo_target_language`
- 再产出 `rewrite_vo_zh_translation`
- 长口播Shot（中文翻译>200字）：保持内部句段数量与节奏断点一致，不合并句段

### 步骤4：长度与质量验证
- 字数：90%-110%
- 情感强度：不低于原版
- 抓人程度：更口语、更直接
- 目标用户匹配（如有输入C）

## 自检清单

逐条给出"通过/不通过+证据"：

1. 是否只在Shot表末尾新增4列，且原列内容完全未改？（首行+3行对照）
2. 是否逐Shot改写且shot_id时间递增？（列出前5个shot_id的start-end）
3. 是否存在跨Shot迁移内容或打乱顺序？（必须"否"）
4. 是否存在照抄/高度重复？（如有列出shot_id并说明改写策略）
5. 每个有口播Shot：`rewrite_vo_zh_translation` 字数是否在 90%-110%？（抽查至少10条，给出原字数/改写字数/比例）
6. 情绪/语气是否对齐 `emotion_state`？（抽查至少10条说明对齐点）
7. 逻辑链条是否保留？（抽查至少10条说明该Shot承担的环节）
8. `ref_frame_timestamp_sec` 是否全部在对应Shot范围内？（抽查至少10条）
9. `ref_frame_basis` 是否每条至少3点依据？（抽查至少5条）
10. 是否无新增承诺/无虚构信息/无改变硬信息含义？
